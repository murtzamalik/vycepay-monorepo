# Mobile Team — Short Code Handoff

**Audience:** Android / iOS  
**Purpose:** Let the customer **generate** and **view** their Choice Bank account short code from the app. Backend is live on BFF.  
**Base URL:** BFF only (never call wallet-service ports directly). Example: `http://app.vycepay.com:9090`

Related:

- [MOBILE_API_CONTRACT_DETAILED.md](MOBILE_API_CONTRACT_DETAILED.md) — success / error envelopes
- [MOBILE_VALIDATE_ACCOUNT_HANDOFF.md](MOBILE_VALIDATE_ACCOUNT_HANDOFF.md) — send money / validate (separate flow)

---

## 1. What is a short code?

A **short code** is a Choice-allocated shorter identifier tied to the customer’s wallet `accountId`. Customers can share it instead of the full account number for collections / receive-money UX.

| Concept | Detail |
|---------|--------|
| Generated by | Choice Bank via `applyForShortCode` |
| Owned by | The logged-in customer’s wallet only |
| Stored where | Choice Bank (source of truth). App may cache for display only. |
| OTP needed? | **No** for generate / view |

---

## 2. Product rules (must follow)

| Rule | Detail |
|------|--------|
| Auth | Bearer JWT required. Do **not** send `X-Customer-Id` — BFF sets it from JWT. |
| Scope | Always the **caller’s** wallet. No `accountId` in the request body. |
| Generate | Call **apply** only when the user taps Generate (or when query shows no code). Do not spam apply on every screen open. |
| View | Prefer **query** when opening the screen. Optionally also show `shortCode` from account details. |
| Empty | If query returns no usable `shortCode`, show “Generate short code” CTA. |
| Copy | Provide copy-to-clipboard on the displayed code. |
| Errors | Show `message` from the error envelope (Choice Bank text when Choice sent one); use `code` for logic; keep `requestId` for support. |

---

## 3. Screen flows

### A) View / generate (primary)

```
1. Open Wallet Account / Receive Money / Short code screen
2. POST /api/v1/wallets/account/short-code/query
3. If shortCode present → show + copy
4. If missing / empty → show “Generate short code”
5. User taps Generate → POST /api/v1/wallets/account/short-code/apply
6. Show returned shortCode + copy
7. Optional: pull-to-refresh → query again
```

### B) Optional — also from account details

```
1. GET /api/v1/wallets/account/details
2. If data.shortCode present → can show on account screen
3. Still use apply/query APIs for dedicated short-code actions
```

### C) Resolve (advanced — usually not needed for generate/view)

`POST .../short-code/resolve` maps a short code → full `accountId`, but **only if it belongs to the logged-in wallet**.  
Do **not** use this to look up *someone else’s* short code for Send Money.

---

## 4. Auth headers

| Header | When |
|--------|------|
| `Content-Type: application/json` | When sending a JSON body (resolve only) |
| `Authorization: Bearer <token>` | **All** short-code APIs |

Do **not** send:

- `X-Customer-Id`
- `Idempotency-Key` (not used on these endpoints)

---

## 5. APIs

Base path: `/api/v1/wallets/account`

All responses use the **success envelope**; Choice payload is in `data`.

### 5.1 Generate short code

`POST /api/v1/wallets/account/short-code/apply`

**Body:** none (empty)

**Success `200`:**

```json
{
  "success": true,
  "code": "WALLET_SHORT_CODE_APPLIED",
  "message": "Short code applied.",
  "requestId": "correlation-id",
  "data": {
    "accountId": "0123456789",
    "shortCode": "VP4829"
  }
}
```

| Field | Use |
|-------|-----|
| `data.shortCode` | Display + copy (primary) |
| `data.accountId` | Optional secondary label / debug |

---

### 5.2 View short code

`POST /api/v1/wallets/account/short-code/query`

**Body:** none (empty)

**Success `200`:**

```json
{
  "success": true,
  "code": "WALLET_SHORT_CODE_QUERY",
  "message": "Short code retrieved.",
  "requestId": "correlation-id",
  "data": {
    "accountId": "0123456789",
    "shortCode": "VP4829"
  }
}
```

**UI tips**

- If `data.shortCode` is null / missing / blank → treat as “not generated yet”.
- Title: “Your short code”
- Subtitle: “Share this instead of your full account number”

---

### 5.3 Resolve short code → account (optional)

`POST /api/v1/wallets/account/short-code/resolve`

```json
{
  "shortCode": "VP4829"
}
```

**Success `200`:**

```json
{
  "success": true,
  "code": "WALLET_SHORT_CODE_RESOLVED",
  "message": "Account resolved from short code.",
  "requestId": "correlation-id",
  "data": {
    "accountId": "0123456789",
    "shortCode": "VP4829"
  }
}
```

**Ownership rule:** If the short code does not belong to the caller’s wallet → error `SHORT_CODE_MISMATCH`.

---

### 5.4 Optional — account details (includes shortCode)

`GET /api/v1/wallets/account/details`

Choice `data` may include `shortCode` among other account fields. Useful for the account overview screen; dedicated generate/view should still use apply/query.

## 6. Error handling

Error envelope:

```json
{
  "code": "ERROR_CODE",
  "message": "Human-readable message",
  "requestId": "correlation-id",
  "details": null
}
```

| `code` | Typical HTTP | Mobile action |
|--------|--------------|---------------|
| `WALLET_NOT_FOUND` | 404 | KYC / wallet not ready — send user to complete onboarding |
| `SHORT_CODE_MISMATCH` | 4xx | Wrong code / not yours — show message (resolve only) |
| `SERVICE_UNAVAILABLE` | 503 | Choice not configured — retry later / contact support |
| `CHOICE_BANK_ERROR` | 502 | Show message; allow retry |
| `UNAUTHORIZED` / missing token | 401 | Re-login |

Always prefer showing `message` to the user (Choice `msg` wins when present on Choice-backed calls). Log `requestId` + `code` for support.

## 7. UI checklist

- [ ] Short code screen (or section on Wallet Account / Receive)
- [ ] On open: call **query**
- [ ] Empty state → **Generate** CTA → **apply**
- [ ] Display `shortCode` prominently + copy button
- [ ] Loading / disabled button while apply or query in flight
- [ ] Error toast/snackbar from envelope `message`
- [ ] Do not call apply in a loop or on every resume
- [ ] Do not invent / edit short codes client-side

## 8. Suggested copy

| State | Copy |
|-------|------|
| Loading | “Loading short code…” |
| Empty | “You don’t have a short code yet.” |
| CTA | “Generate short code” |
| Success apply | “Short code created” |
| Has code | “Your short code” + value |
| Copy | “Copied” |
| Error | Use server `message` |

---

## 9. Out of scope (this handoff)

- Paying **another person** via their short code (use existing send / validate flows; do not misuse resolve)
- Storing short codes in local DB as source of truth (Choice remains source of truth)
- Backend changes — APIs are already live
